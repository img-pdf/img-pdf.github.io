2. How Document Stream Merging Works Behind the Scenes

A PDF file is not a simple image; it is an organized database of document streams containing page trees, font dictionaries, form fields, and vector drawings. When you merge PDFs properly:

  1. The PDF engine parses the Root Catalog and Pages Tree of each input document.
  2. Individual page objects (/Page) and their dependent content streams (/Contents) are re-indexed to prevent object ID collisions.
  3. A consolidated root catalog is generated, preserving text selectable status and hyperlink integrity.

Using client-side WebAssembly and modern JavaScript libraries like pdf-lib, ImgPDF performs this entire synthesis directly within your device's browser memory.

4. Controlling Page Sequences and Document Structure

When assembling files from various sources, you will often encounter mixed orientations (such as a landscape financial spreadsheet merged between portrait letter pages). Modern PDF specifications support per-page rotation dictionaries (/Rotate 90, /Rotate 180, /Rotate 270), meaning each page maintains its proper viewing angle automatically upon merge without warping text.

6. Frequently Asked Questions

Is there a limit to how many PDFs I can merge?
ImgPDF does not enforce artificial file limits. You can merge 2, 10, or 50+ files smoothly, constrained only by your device's available memory.
Does merging PDFs affect digital signatures?
Cryptographic digital signatures (PKI signatures) are designed to become invalid if document structure changes. If a PDF contains an active cryptographic signature, merging it into a new document will invalidate the original certificate stamp, though the visual signature line will remain intact.
